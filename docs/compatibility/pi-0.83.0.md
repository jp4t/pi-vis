# Pi 0.80.10 → 0.83.0 compatibility audit

Audited against the upstream coding-agent changelog and the shipped public declarations/runtime from `v0.80.10` through `v0.83.0` on 2026-08-01. Production Pi-Vis bundles and runs exactly `@earendil-works/pi-coding-agent@0.83.0` (see `src/main/pi/pinned-pi.ts`); it never detects or runs a user-installed Pi. Tests use that same repository-local package. Changing the pin is a Pi-Vis release decision and requires repeating this audit.

## Pi 0.83.0 handling

| Upstream change | Pi-Vis handling |
|---|---|
| Credential export (`pi auth print-api-key` / `print-bearer-token`) and early OAuth refresh | The feature remains owned by the exact bundled CLI and public `ModelRuntime`. It is not reimplemented as a renderer command, so credentials never enter IPC, authority outcomes, Zustand, replay, or logs. The pin gate executes `print-api-key` against an isolated agent directory and checks that both commands are present. Pi-Vis login/model requests inherit the runtime's five-minute refresh threshold. |
| `ExtensionContext.scopedModels` | Each runtime-factory invocation resolves saved `enabledModels` through public `resolveModelScopeWithDiagnostics()` and passes the resulting `{ model, thinkingLevel? }` entries to `createAgentSessionFromServices()` before extensions bind. A fresh session chooses the configured default when it is in scope, otherwise the first scoped model; persisted zero-message identity and a resolvable non-null same-session resume model retain precedence. A null resume model intentionally uses Pi's scope/settings fallback while retaining resume thinking. Empty/no-match scope remains unrestricted. The picker fallback stays defensive for legacy/test sessions. |
| Headless OpenRouter sign-in | Pi 0.83 races the loopback callback against a `manual_code` prompt. The persistent app-owned auth surface carries the preceding authorization URL and instructions into that prompt revision, so **Open browser** and redirect/code entry are available together. Prompt values are cleared before IPC and never retained in authority/replay state. |
| Direct RPC `user_bash` interception | Pi-Vis's SDK-direct `!` / `!!` path now mirrors Pi RPC: it calls public `ExtensionRunner.emitUserBash()` exactly once. The hook awaits outside serialized ingress and re-enters it for mutable revalidation/start/receipt. Escape or legacy abort fences a pending hook, preserves the stable draft as `not_admitted/cancelled`, and consumes late settlement. An extension-supplied full result is recorded without spawning; replacement `BashOperations` stream through a non-PTY Shell Turn; an unhandled command keeps the host-owned interactive PTY. All paths retain the stable execution ID, canonical Bash persistence, context-exclusion flag, and one start/end transcript lifecycle. |
| Per-request `fetch`, `StopReason.pending`, and `rawStopReason` | Pi-Vis does not wrap provider transports or rebuild assistant messages. The public runtime receives request options unchanged, while wire/session schemas intentionally retain message fields with passthrough objects. Pin tests gate the new declarations. Unmapped terminal provider reasons therefore become Pi errors instead of false successful stops. |
| TypeBox 1.3.7 | The nested exact version is release-gated. Pi-Vis does not call the removed TypeBox aliases; extension tool definitions remain owned by Pi and flow through unchanged. This also inherits the nullable-array compiled-validation fix. |
| GitHub Copilot Claude Opus 5, Qwen/Z.AI/Bedrock/provider fixes, and model catalog changes | These are owned by the pinned `pi-ai` model/provider runtime. Pi-Vis reads provider/model metadata dynamically and does not maintain a second provider catalog, capability map, or reasoning-level table. |
| System-prompt/context/package metadata fixes | `createAgentSessionServices()` and its public resource loader own system/append prompt discovery, nested-worktree context de-duplication, package-source metadata, and clean Git-package retry behavior. Pi-Vis neither copies nor narrows those resources. The corrected `SYSTEM.md` / `APPEND_SYSTEM.md` **interactive startup listing** belongs to Pi's terminal UI and is not rendered by Pi-Vis; the underlying resource contents still flow through the same public services. |
| Session replacement/navigation fixes | Pi 0.83 aborts and persists an outgoing active response before replacement and refuses active-response tree navigation. Pi-Vis additionally keeps its stricter owner/idle/custody/transition admission fences, so renderer requests cannot race those SDK boundaries. |
| Concurrent user-bash cancellation | Public `AgentSession.abortBash()` now cancels every active controller. Pi-Vis routes Escape and lifecycle cleanup through that public method, adds a host fence for pre-controller `user_bash` preparation, and guards PTY plus non-PTY compatibility requests as one foreground Shell Turn. SDK/extension-owned concurrency still receives the upstream fix. |
| llama.cpp streamed usage | The renewed private adapter injects the unchanged hidden factory through the public resource-loader option. Pi 0.83's provider now advertises streaming usage support, so the existing usage-preserving transcript/context paths receive non-zero local-model accounting. |
| Interactive startup duplicate-message fix | Pi-Vis does not instantiate Pi's `InteractiveMode`; renderer session replacement is owned by its epoch-fenced authority protocol. The upstream duplicate-message fix is therefore not a separate GUI code path, while the bundled CLI inherits it unchanged. |
| Image fallback-path presentation fix | Pi-Vis renders image attachments and fallback metadata in React rather than Pi's narrow-terminal fallback view. Terminal wrapping, home shortening, and terminal hyperlinks are interactive-CLI-only; the bundled CLI still inherits the fix. |
| Interactive-only presentation fixes | Pi-Vis owns its React model picker and tool disclosures. Its model filter already moves the highlight to the first match; terminal-only tool-expansion status copy is not a Pi-Vis interaction. |

## Earlier integration-significant handling

| Upstream change | Pi-Vis handling |
|---|---|
| Summarization retry lifecycle (`summarization_retry_scheduled`, `summarization_retry_attempt_start`, `summarization_retry_finished`) | The typed event contract recognizes all three events. State authority projects retry wait/attempt transitions onto the existing compaction or navigation operation, keeps compaction/navigation custody fenced during backoff, and waits for the surrounding operation's own terminal evidence before draining. |
| Tool, compaction, and branch-summary usage accounting | The shared usage schema preserves Pi's public usage/cost value on live tool results, persisted tool messages, compaction results/entries, and branch-summary entries. History hydration and the transcript reducer keep it on the corresponding block. The context meter refreshes after turns, compaction, and a completed navigation that persisted a branch summary, plus its safety poll. |
| Public `AgentSession.getAvailableThinkingLevels()` | Each direct authority snapshot calls the public method when present and projects the result. The thinking picker uses that authoritative list; its model-capability calculation remains only a compatibility/presentation fallback. |
| Public `ExtensionRunner.emitInput()` result | The SDK bridge observes the final `continue` / `transform` / `handled` result once under the owning prompt's admission context. An unchanged `continue` preserves exact queued-steer identity and deletion even when passive input hooks are installed; transformed, handled, nested, and handler-side-effect queue work remains unowned. |
| Messages queued during compaction retain their requested lane | Pi owns this fix internally. Pi-Vis continues to submit through public prompt/queue APIs and never rewrites Pi's selected steering/follow-up lane. |
| Native provider extensions and provider lifecycle types | `createAgentSessionServices()` discovers and registers native provider extensions before Pi-Vis creates the session. Pi-Vis uses only the returned public `ModelRuntime`; it does not copy or narrow provider definitions, so provider-specific auth, model transformation, streaming, and constrained-sampling capability metadata flow through unchanged. |
| Qwen token providers, OpenRouter/Kimi interactive auth, Anthropic bearer auth, provider/model catalog updates, and ETag refresh | These are implemented by the pinned public `ModelRuntime` and bundled `pi-ai`. Pi-Vis's owner-bound login and refresh intents call that runtime directly. Model pickers perform silent stale-while-revalidate refresh on open and after auth changes. Credentials and provider errors never enter authority outcomes. |
| Public diagnostic model-scope resolution and unavailable configured patterns | Every saved-pattern, picker-initialization, model-dropdown, live-scope, and runtime-construction path calls Pi's public `resolveModelScopeWithDiagnostics()`. Pi therefore owns exact/partial/name/glob matching, colon-bearing IDs, thinking suffixes, canonical order, and deduplication. Only `no-match` diagnostics become removable `Unavailable` rows; an `invalid-thinking-level` warning that still resolves a model does not create a false stale row. An unavailable pattern does not make “all available models” a restrictive live session scope, while persistence still retains the stale pattern. |
| Constrained tool sampling | Pi-Vis does not wrap or reconstruct extension tool definitions. `Tool.constrainedSampling` and provider capability flags therefore pass from public extension/provider registration into the pinned agent core unchanged. |
| Direct bash streaming and correlated `bash_execution_update` | `runBash` and the compatibility `bash` command pass their stable request/intent ID to public `AgentSession.executeBash()`. The child brackets Pi's correlated update events with Pi-Vis-owned start/end transcript events, producing one live or extension-backed Shell Turn, one normalized settled record, and one terminal operation outcome. `!!` preserves `excludeFromContext`. |
| Bash session/model environment variables | Built-in agent bash tools are created by Pi's public SDK factory, so `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, and `PI_REASONING_LEVEL` are supplied by the pinned runtime. Pi-Vis does not replace the built-in bash tool or import private Pi internals. |
| `MessageRenderOptions.outputPad` | Custom-message rendering passes the public settings manager's current output padding to the registered message renderer. Entry renderers retain their distinct `EntryRenderOptions` contract. |
| Local llama.cpp model management | Upstream still installs this as a hidden CLI-main built-in and does not export its factory from the public SDK entry. [ADR 0006](../decisions/0006-pinned-llama-private-extension-exception.md) renews one exact-version adapter: it derives the shipped `dist/extensions/index.js`, selects only the hidden `llama.cpp` factory, validates its shape, and injects it through public `resourceLoaderOptions.extensionFactories`. `/llama`, `/login llama.cpp`, router catalog/load/unload/download/retry behavior, the native provider, and Pi-TUI custom panel then run unchanged from Pi 0.83.0. |
| Remaining provider/core fixes | Fallback streaming, custom OpenAI-compatible tools, Google/Anthropic header and reasoning fixes, model catalog changes, scoped API-key visibility, and llama catalog persistence are owned by the pinned `pi-ai`/coding-agent runtime and require no Pi-Vis protocol adaptation. |

The earlier SDK-host integrations remain in force: `agent_settled`, custom entry/message rendering, extension command errors, cache-miss notices, optional session names, `ThinkingLevel.max`, zero-message model/thinking restoration, confined runtime aliases, prompt preflight fencing, project trust, and the public `ModelRuntime` adapter. The host's 0.80.6–0.80.7 public-surface adapter paths remain testable but are unreachable in production while the exact pin is 0.83.0.

## Authority compatibility

Pi 0.83.0 supplies the public getters and methods the host snapshots directly: streaming/idle/compaction/retry/bash state, model/session metadata, available thinking levels, pending queues, prompt preflight, queue clearing, navigation, abort primitives, and the canonical model/auth runtime. Snapshot identity, epoch, sequence, leases, submission custody, editor revisions, and queue restoration remain Pi-Vis protocol features around those public APIs.

Compaction still clears its getter immediately after the synchronous terminal callback, so the host retains its conservative microtask reconciliation barrier. Summarization backoff is part of the same observed compaction/navigation span rather than a synthetic terminal operation. A compact invocation drains custody only after both public lifecycle/getter reconciliation and the public `compact()` promise settle.

## Regression gates

`tests/pinned-pi-runtime.test.mts` gates the manifest pin, installed coding-agent/core/AI/TUI and TypeBox versions, executable layout, credential-export CLI, and the 0.81–0.83 public declarations/runtime exports Pi-Vis consumes. `pinned-pi-private.test.mjs` checks the installed public version before gating the one private llama registry path; `host-imports.test.ts` prohibits every second private host dependency. Host, protocol, reducer, history, picker, login, and renderer tests cover retries, usage, public thinking constraints, Pi-owned model scopes plus `ctx.scopedModels`, unavailable scopes, `user_bash`, correlated bash streaming, headless OAuth, and `outputPad`.

The real SDK suites (`tests/e2e/real-sdk-host-smoke.spec.mts`, `real-sdk-transcript-lifecycle.spec.mts`, `real-sdk-shell-turns.spec.mts`, `real-sdk-regressions.spec.mts`, `real-sdk-races.spec.mts`, `authority-faults.spec.mts`, and `llama-manager.spec.mts`) run the exact local 0.83.0 executable in isolated directories with loopback providers where model work is needed. The Shell Turn gate exercises public `user_bash` full-result and replacement-operation handlers, including a real renderer reload and reselection of the same live session between workspace-gated operation chunks to prove bounded non-PTY attach reconstruction and sequence deduplication. The regression extension observes the configured scope through `ctx.scopedModels` at bind time. The llama gate configures a fake router through the production `settings.piEnv` path, renders the real manager panel, closes it through the panel-input Escape path, and selects its synchronized native-provider model. Run `npm run test:e2e:real-pi` for that focused gate or `npm run test:full` for the release gate.
